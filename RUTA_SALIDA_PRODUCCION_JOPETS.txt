FASE 1 - CONGELAR Y RESPALDAR EL CÓDIGO
----------------------------------------
1. Crear la rama de release:
   git checkout -b release/0.1.0

2. Configurar y verificar el remoto GitHub:
   git remote -v

3. Subir el código:
   git push origin main
   git push origin release/0.1.0

4. Crear la etiqueta de release candidate:
   git tag -a v0.1.0-rc1 -m "Jopets release candidate 1"
   git push origin v0.1.0-rc1

RESULTADO ESPERADO:
El código queda respaldado, versionado y recuperable.

FASE 2 - PREPARAR EL VPS
------------------------
Instalar y configurar:
- Docker Engine.
- Docker Compose.
- PostgreSQL 16.
- Redis.
- Nginx.
- Certbot.
- Dominio apuntando al VPS.
- Firewall con únicamente los puertos necesarios.

Puertos recomendados:
- 80 para HTTP.
- 443 para HTTPS.
- SSH restringido por IP o llave.

Crear el archivo .env real en el VPS. No subirlo a GitHub.

Variables mínimas:
DJANGO_SECRET_KEY=
DJANGO_DEBUG=false
ALLOWED_HOSTS=
POSTGRES_DB=
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_HOST=
POSTGRES_PORT=5432
REDIS_URL=redis://redis:6379/0
PAYMENT_WEBHOOK_SECRET=
API_BASE_URL=https://api.TU_DOMINIO.com

También configurar:
- CORS permitido.
- CSRF trusted origins.
- Dominio del panel global.
- Configuración de correo.
- Credenciales de almacenamiento si se utilizan.
- Credenciales de pagos únicamente en staging inicialmente.

FASE 3 - BASE DE DATOS Y MULTI-TENANT
-------------------------------------
1. Ejecutar migraciones:
   docker compose run --rm backend python manage.py migrate

2. Verificar:
   docker compose run --rm backend python manage.py check

3. Activar realmente RLS en PostgreSQL.

4. Confirmar que las tablas críticas tengan:
   - ENABLE ROW LEVEL SECURITY.
   - FORCE ROW LEVEL SECURITY.
   - Políticas USING.
   - Políticas WITH CHECK.
   - Contexto jopets.tenant_id.
   - Contexto jopets.parent_tenant_id.

5. Crear dos tenants de prueba: Tenant A y Tenant B.

6. Verificar aislamiento:
   - Un usuario de A no puede leer mascotas de B.
   - Un usuario de A no puede leer reservas de B.
   - Un proveedor de A no puede consultar wallet de B.
   - Un proveedor recibe 403 en endpoints exclusivos del dueño.
   - Un usuario global solo accede a las vistas administrativas autorizadas.

RESULTADO ESPERADO:
La base de datos está migrada y el aislamiento está demostrado con pruebas reales.

FASE 5 - REDIS, ASGI Y CHAT
---------------------------
1. Confirmar Redis:
   redis-cli ping

La respuesta esperada es:
   PONG

2. Ejecutar el backend mediante ASGI/Daphne:
   daphne -b 0.0.0.0 -p 8000 config.asgi:application

3. Crear dos usuarios reales:
   - Un dueño.
   - Un proveedor.

4. Verificar:
   - Ambos pertenecen al tenant correcto.
   - La reserva contiene provider_id.
   - El WebSocket recibe tenantId y peerId.
   - El mensaje llega en tiempo real.
   - El mensaje se guarda en la base de datos.
   - Un usuario no autorizado es rechazado.
   - El JWT expirado cierra la conexión.

FASE 6 - PAGOS EN STAGING
-------------------------
1. Elegir una sola pasarela inicial:
   - Stripe, PayPhone o Kushki.

2. Mantener SandboxAdapter únicamente durante las pruebas internas.

3. Implementar el flujo completo:
   Checkout Flutter
   -> Crear intención de pago
   -> Proveedor de pagos
   -> Webhook firmado
   -> Transacción
   -> Reserva paid
   -> Splits de proveedor/subdueño/SIMA
   -> Wallet del proveedor

4. Verificar:
   - Idempotencia.
   - Firma del webhook.
   - Eventos duplicados.
   - Pago rechazado.
   - Pago cancelado.
   - Reembolso.
   - Moneda.
   - Comisiones.
   - Redondeo Decimal.
   - Registro exacto de los montos.

IMPORTANTE:
El webhook actualmente puede cambiar la reserva a paid, pero debe conectarse al flujo financiero completo de transacciones, comisiones y wallet.

FASE 8 - COMPILACIÓN FLUTTER RELEASE
------------------------------------
Configurar la URL real de la API:

flutter build apk --release \
  --dart-define=API_BASE_URL=https://api.TU_DOMINIO.com \
  --dart-define=JOPETS_TENANT_ID=TU_TENANT_ID

Para generar el archivo de publicación:

flutter build appbundle --release \
  --dart-define=API_BASE_URL=https://api.TU_DOMINIO.com \
  --dart-define=JOPETS_TENANT_ID=TU_TENANT_ID

Configurar firma Android:
- Crear keystore de producción.
- Configurar key.properties.
- Configurar firma release.
- Guardar el keystore en un lugar seguro.
- No subir el keystore a GitHub.
